# PDHD fragment-freeze protocol

## Purpose

Fragment freezing converts the 24 selected pilot documents into a fixed set of **96 source-localized units** before any independent coding begins. The objective is to ensure that coders receive exactly the same evidentiary units and that later disagreement reflects label application rather than hidden differences in source selection.

`fragment_freezing != annotation`

No pedagogical label is assigned during this pass.

## Deterministic slot structure

Every selected document contributes four slots generated by `scripts/build_fragment_manifest.py`:

- **A — explicit pedagogical act:** a passage containing an explicit pedagogical action or instructional prescription;
- **B — institutional relation:** a passage concerning professional identity, authority, supervision, evaluation or organization;
- **C — source-criticism salient:** a historically significant passage chosen because of the documentary context rather than a predetermined keyword target;
- **D — control:** a passage capable of receiving `none` or `unclear` for at least one coded field.

The slot design prevents the reliability corpus from containing only obvious positive examples.

## Required fields at freeze time

A fragment may move from `pending_locator` to `frozen` only when the following are resolved:

- immutable `fragment_id`;
- `document_id`;
- page number or stable source locator;
- fragment boundaries;
- transcription status;
- access basis;
- public-text handling status;
- selection role;
- preparation note sufficient to reconstruct why the passage was chosen.

A fragment does **not** require a public full-text transcription to be frozen. If rights or platform conditions make public transcription inappropriate, PDHD may freeze the page/localizer and keep coder text in a controlled local working file.

## Access classes

Use one of the following working access decisions:

- `public_text_permitted` — a documented basis allows the relevant text to be stored publicly;
- `short_excerpt_only` — only a limited research excerpt is stored publicly;
- `coder_local_text` — the public repository stores locator and metadata while the text used by coders remains outside GitHub;
- `metadata_only` — the object can be selected or referenced but text extraction is not authorized or not yet technically available;
- `access_unresolved` — freeze cannot be completed until access is clarified.

The access decision concerns PDHD's handling of the digital representation. It does not alter the copyright status of the underlying historical work.

## Transcription status

Use controlled preparation statuses:

- `source_text_verified` — transcription checked against the source image/text;
- `ocr_human_corrected` — OCR corrected by a human against the source;
- `ocr_unverified` — machine OCR exists but has not been checked;
- `manual_transcription_unverified` — manually entered text has not yet received a second check;
- `not_transcribed` — coders will consult the permitted source interface or a controlled image/PDF locally;
- `not_started` — no transcription decision yet.

Unverified OCR must never be silently presented as historical quotation.

## Page and boundary rule

The fragment should be the smallest span that preserves the historical meaning needed for coding. A sentence may be sufficient; a paragraph or short multi-paragraph span may be required where prescriptions, actors or qualifications cross sentence boundaries.

Boundary selection should not be optimized to force a desired category. When surrounding context changes the apparent meaning, include the required context or flag the fragment for review.

## Blindness rule

The preparation pass may use lexical search, retrieval systems or model assistance to locate candidate passages. However, the final coder package must not expose:

- predicted `pedagogical_act`;
- predicted dimensions;
- model confidence;
- another coder's annotations;
- adjudicator expectations.

Preparation metadata may describe the slot role because all coders receive the same role structure, but it must not contain a proposed answer.

## Source-specific constraints

### HNDM

Public repository handling remains `metadata_only` unless a stronger permission basis is documented. The fragment can still be frozen by page/localizer for local coding where access is lawful, but PDHD does not publish HNDM page images or full OCR by default.

### HathiTrust

Stable catalog and full-view records establish object identity and research access. In the current environment, automated requests to the Babel page-image endpoint can return HTTP 403. Such a failure is an access-technical fact, not evidence that the source is absent. Manual or institutionally permitted consultation may therefore be required to freeze exact pages.

### Google Books

Searchable snippets, full-view records and free-ebook availability may support page discovery. PDHD does not infer that Google-hosted scans or OCR can be mirrored. Public fragment text requires a separate reuse decision.

### UNAM and Cervantes

Object-level rights metadata or platform terms are reviewed before deciding whether text is public, excerpt-only or coder-local. Digital availability alone is not treated as an unrestricted license.

## Quality control

Before the pilot package is released to coders, a preparation reviewer should verify all 96 rows for:

1. resolvable source locator;
2. readable evidence;
3. non-duplicated fragment boundaries;
4. correct slot role;
5. absence of leaked model labels;
6. rights-compatible public handling;
7. stable fragment ID.

The manifest generator is deterministic and checked in CI, but CI cannot verify historical appropriateness of a passage. That remains a human source-criticism task.

## Completion gate

Fragment freezing is complete only when **96/96** slots are `frozen` or when an explicitly documented substitution replaces an inaccessible selected document without violating the pilot stratification rules.

If a document must be substituted, the reason, outgoing document, replacement document and effect on era, geography, documentary type and publication concentration must be versioned before the coding round begins.

After 96 fragments are frozen, PDHD creates the 12-fragment calibration set, runs calibration, freezes the codebook version, and only then begins independent coding.
